# gemini-proxy: обёртка для self-hosted деплоя

Разворачивает [lehuygiang28/gemini-proxy](https://github.com/lehuygiang28/gemini-proxy) на своём сервере: HTTPS со своим сертификатом и исходящие запросы через прокси. Исходников апстрима здесь нет — Docker тянет их сам, по коммиту из `UPSTREAM_REF`.

## Запуск

```bash
cp .env.example .env
```

Заполни `.env` (что именно — ниже), положи сертификат и подними:

```bash
docker compose up -d --build
```

Первая сборка идёт долго: ставится вся монорепа апстрима и собирается Next.js.

После старта открой в Supabase раздел Authentication, страницу URL Configuration, и пропиши `https://<домен>` в Site URL, а `https://<домен>/**` в Redirect URLs. Без этого логин в дашборд не отработает.

## Что нужно заполнить

Правится `.env`, а не `.env.example`: первый в игноре, второй лежит в гите и уедет на GitHub вместе с тем, что ты в него впишешь.

Supabase — внешняя база, своего хранилища у прокси нет. Там лежат пул гугловых ключей, твои прокси-ключи, логи запросов и пользователи дашборда. Заводится отдельно, схема накатывается по [docs/getting-started.md](https://github.com/lehuygiang28/gemini-proxy/blob/main/docs/getting-started.md) апстрима, оттуда же берутся четыре переменные. `NEXT_PUBLIC_*` попадают в браузерный бандл, поэтому там анонимный ключ; `SUPABASE_SERVICE_ROLE_KEY` ходит мимо RLS и живёт только на сервере.

В `DOMAIN` пиши то, на что выписан сертификат. Домена может и не быть: IP-адрес Caddy принимает как адрес сайта, ACME при явном `tls` не включается. Тогда сервис доступен по `https://<ip>`, и этот же адрес надо прописать в Supabase, иначе логин в дашборд не пройдёт. Браузер примет такой сертификат, только если IP указан в SAN.

`CERT_DIR` — каталог с сертификатом на хосте, монтируется в контейнер как `/certs`. Caddy по умолчанию ищет там `cert.pem` и `key.pem`; если файлы называются иначе, задай `TLS_CERT` и `TLS_KEY` путями внутри `/certs`. В сертификате должна быть полная цепочка.

Переменную `HTTPS_PROXY` заполняй, если исходящие запросы к Google и Supabase должны идти через прокси. Пусто — ходят напрямую. Работают только HTTP(S)-прокси: под капотом нативный флаг ноды `--use-env-proxy`, SOCKS он не умеет. Прокси на самом хосте пишется как `http://host.docker.internal:PORT`, и тогда сервису нужен `extra_hosts: ["host.docker.internal:host-gateway"]` — на Linux этот адрес сам не резолвится.

## Как устроено

`caddy` слушает 80 и 443, терминирует TLS и проксирует всё в `web`. Наружу торчит только он.

`web` — Next.js-дашборд апстрима. Он же отдаёт сам прокси: `/v1/*` и `/api/gproxy/*`. То есть после `docker compose up` рабочая ручка — `https://<домен>/v1`, а на `/` живёт админка.

`api` — отдельный Hono-сервер апстрима с теми же ручками, легче и быстрее Next.js. Он дублирует `web` и по умолчанию не поднимается. Если нужен отдельно:

```bash
docker compose --profile api up -d
```

Слушает он `127.0.0.1:9090`, наружу не смотрит.

## Деплой на сервер

Хост и каталог задаются одной переменной в `.env`: `GPROXY_REMOTE=myserver:~/gemini-proxy-docker/`. Хост берётся из твоего `~/.ssh/config`, отдельных настроек скрипту не нужно.

```bash
./sync.sh
```

Заливает `Dockerfile`, `docker-compose.yml`, `Caddyfile`, `README.md` и сам себя, потом делает `up -d --build`. Отдельные шаги: `code` — только залить, `up`, `restart`, `logs`, `--rebuild` — собрать мимо кэша слоёв.

Серверный `.env` живёт своей жизнью и по `./sync.sh` не перезаписывается: на сервере другой домен и свои ключи. Отправить локальный целиком — `./sync.sh env`. Сертификаты не едут вообще, они лежат на сервере в каталоге из `CERT_DIR`.

## Обновить апстрим

По умолчанию собирается свежий `main` апстрима. Пересборка подтянет его заново, даже если Docker всё закэшировал: перед клоном сборка дёргает GitHub API за текущим коммитом ветки, и ответ ломает кэш, когда апстрим сдвинулся.

```bash
docker compose up -d --build
```

Чтобы прибить конкретную версию, задай в `.env` коммит, тег или ветку:

```
UPSTREAM_REF=5d6c9ade5c250b8be576ae5a5545d05ed193f87d
```

Зависимости переустановятся только если в новом коммите поменялся лок-файл: манифесты копируются в сборку отдельным слоем.

Ставить апстрим пакетом из npm нельзя — опубликован только CLI для управления инстансом, а `@gemini-proxy/core` и дашборд в реестр не выкладываются.

## Чего здесь нет

Апстрим не пропатчен ни в одном месте, все правки живут в этих трёх файлах: `Dockerfile`, `docker-compose.yml`, `Caddyfile`.

Healthcheck'ов, лимитов ресурсов и автопродления сертификата нет. Caddy умеет выпускать сертификат сам — если свой не нужен, поменяй в `Caddyfile` пути на `tls твоя@почта`.
