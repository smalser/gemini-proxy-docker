# gemini-balance: обёртка для self-hosted деплоя

Разворачивает [gemini-balance](https://github.com/snailyp/gemini-balance) на своём сервере: пул гугловых ключей с ротацией, HTTPS со своим сертификатом, исходящие запросы через прокси. Два контейнера, внешней базы нет — состояние лежит в SQLite-файле рядом.

## Запуск

```bash
cp .env.example .env
```

Заполни `.env`, положи сертификат в каталог из `CERT_DIR` и подними:

```bash
docker compose up -d
```

Образ готовый, ничего не собирается. Дальше заходи на `https://<домен>` с паролем из `AUTH_TOKEN` — там веб-морда со статусом ключей и логами.

## Что заполнить

`API_KEYS` — гугловые ключи, между которыми крутится нагрузка. Сдохший на 429 ключ отключается сам после `MAX_FAILURES` неудач и возвращается в строй по таймеру.

`ALLOWED_TOKENS` — ключи, которые ты раздаёшь клиентам; агент присылает такой как свой `api_key`. `AUTH_TOKEN` — вход в админку.

Оба списка — JSON-массивы, а не строки через запятую: `["sk-раз","sk-два"]`.

`PROXIES` — исходящий прокси, тоже списком. Понимает и `http://`, и `socks5://`, логин с паролем пишутся прямо в URL. Пустой список — Google зовётся напрямую.

`DOMAIN` — то, на что выписан сертификат. Домена может и не быть: IP Caddy принимает как адрес сайта, ACME при явном `tls` не включается. Браузер и клиенты примут такой сертификат, только если IP прописан в SAN.

Остальные переменные gemini-balance описаны в [его README](https://github.com/snailyp/gemini-balance/blob/main/README.md), любую можно дописать в `.env`. Часть настроек правится ещё и в веб-морде — они переезжают в базу и оттуда побеждают.

## Куда ходить агентам

Прямо на твой сервер, ключом из `ALLOWED_TOKENS`. Ничего, кроме него, клиенту знать не нужно.

- OpenAI-совместимый API: `https://<домен>/openai/v1`
- нативный Gemini: `https://<домен>/gemini/v1beta`

То есть в конфиге агента base URL — первый адрес, api key — твой `sk-...`.

## Как устроено

`caddy` слушает 80 и 443, терминирует TLS и проксирует всё в приложение. Наружу торчит только он, порт 8000 остаётся внутри docker-сети.

`gemini-balance` — готовый образ `ghcr.io/snailyp/gemini-balance`. Ключи, логи запросов и настройки пишет в `data/` рядом с compose-файлом.

Ротация, ретраи и подсчёт расхода живут внутри приложения; обёртка добавляет к нему только TLS и деплой.

## Деплой на сервер

Хост и каталог задаются одной переменной в `.env`: `GPROXY_REMOTE=myserver:~/gemini-proxy-docker/`. Хост берётся из твоего `~/.ssh/config`.

```bash
./sync.sh
```

Заливает `docker-compose.yml`, `Caddyfile`, `README.md` и сам себя, потом поднимает контейнеры. Отдельные шаги: `code` — только залить, `up`, `update` — подтянуть свежий образ, `restart`, `logs`.

Серверный `.env` по `./sync.sh` не перезаписывается: там боевые ключи. Отправить локальный целиком — `./sync.sh env`. Сертификаты и `data/` не едут вообще, они живут на сервере.

## Чего здесь нет

Апстрим не пропатчен: вся обёртка — это `docker-compose.yml`, `Caddyfile` и `sync.sh`.

Бэкапов `data/` нет. Там лежат гугловые ключи и клиентские токены, так что каталог стоит забирать к себе, если не хочешь заводить их заново.

Файрвола тоже нет. Порт 8000 наружу не проброшен, но 80 и 443 открыты всем — доступ ограничивает только `ALLOWED_TOKENS`.
